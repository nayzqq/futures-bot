# Futures Sentiment Bot (MVP)

Telegram-бот, который следит за топ-10 крипто-монетами по капитализации,
собирает мнения из новостей (RSS), Reddit и CryptoPanic, и присылает
**алерт**, когда по монете резко растёт число бычьих или медвежьих
упоминаний за короткое время.

## Архитектура: данные важнее мнений

Сигналы разбиты на 3 категории по надёжности:
- **market** (самая надёжная) — funding rate, Open Interest и резкие движения
  цены напрямую с бирж (Bybit, с fallback на OKX). Публичные эндпоинты,
  ключ не нужен.
- **news** — RSS (CoinDesk, CoinTelegraph, Decrypt) + CryptoPanic
  (новости + голоса сообщества)
- **social** — Reddit, **выключено по умолчанию** (см. предупреждение ниже)

**Алерт срабатывает, только когда минимум 2 РАЗНЫЕ категории сошлись
в одном направлении** за одно и то же окно времени. Одна новость или
один разгорячённый сабреддит сами по себе алерт не вызовут — нужно,
чтобы это подтвердилось реальным движением рынка (или наоборот).
Это резко снижает число ложных срабатываний по сравнению с одним источником.

Дополнительно к каждому алерту подтягивается **Fear & Greed Index**
(alternative.me, бесплатно) — как общий контекст рынка в тексте
уведомления, не как отдельная категория (индекс общий на весь рынок,
не по конкретной монете).

Топ-10 монет обновляется автоматически через CoinGecko (раз в сутки).
Кулдаун не даёт спамить повторными алертами по одной монете.
Команда `/status` — сводка по всем монетам за 24 часа.

## Что НЕ включено (сознательно, для MVP)
- X/Twitter — официальный API платный, скрейпинг нарушает ToS
- TradingView идеи — нет публичного API, парсинг рискован по ToS
- LLM-классификация тональности (сейчас — просто ключевые слова).
  Это можно улучшить позже, прогоняя заголовки через Claude/OpenAI API.

## ⚠️ Про Reddit (важно, обновление 2026)
С ноября 2025 Reddit закрыл самостоятельную выдачу API-ключей — теперь
любой доступ к данным требует предварительного ручного одобрения от
Reddit (Responsible Builder Policy), и для обычного личного бота такое
одобрение получить практически нереально. Форма на
`reddit.com/prefs/apps` может просто не пропускать заявку.

**Что делать**: не трать на это время — в `.env` уже стоит
`ENABLE_REDDIT=false` по умолчанию, сборщик Reddit просто не запускается,
остальные категории (market + news) продолжают работать и этого
достаточно для срабатывания алертов. Код Reddit-коллектора оставлен в
проекте на случай, если у тебя когда-то будет одобренный доступ —
тогда включи флаг и заполни ключи.

Как более реалистичная замена соцсигналов можно позже добавить
**LunarCrush** (lunarcrush.com) — у них есть публичный free-tier API
именно под социальный сентимент по крипте, без такой бюрократии.

## Установка

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Дальше заполни `.env`:

1. **Telegram**: напиши @BotFather, `/newbot`, получи токен →
   `TELEGRAM_BOT_TOKEN`. `TELEGRAM_CHAT_ID` — узнать можно, написав своему
   боту любое сообщение и посмотрев `chat.id` в апдейте (или через бота
   @userinfobot для личного чата).
2. **Reddit**: зайди на https://www.reddit.com/prefs/apps, "create app",
   тип **script**, получишь `client_id` (под названием приложения) и
   `client_secret`.
3. **CryptoPanic**: зарегистрируйся на https://cryptopanic.com/developers/api/,
   получишь бесплатный `auth_token`.

Можно оставить Reddit или CryptoPanic пустыми — соответствующий сборщик
просто пропустится (в логах будет предупреждение), RSS работает всегда
и без ключей.

## Запуск

```bash
python main.py
```

При старте бот сразу делает первый сбор данных, дальше — по расписанию
(по умолчанию раз в 5 минут, настраивается в `.env` через
`COLLECT_INTERVAL_SECONDS`).

## Настройка чувствительности алертов

Общее (в `.env`):
- `ALERT_WINDOW_MINUTES` — окно наблюдения (по умолчанию 20 мин)
- `ALERT_COOLDOWN_MINUTES` — не повторять алерт по монете чаще, чем раз в N минут (60)

По категории **market** (биржевые данные):
- `MARKET_PRICE_SPIKE_PCT` — на сколько % должна скакнуть цена за окно (2.5)
- `MARKET_OI_SPIKE_PCT` — на сколько % должен измениться Open Interest (5.0)
- `MARKET_FUNDING_EXTREME_PCT` — при каком funding rate считать перекос экстремальным (0.05)

По категориям **news** и **social**:
- `NEWS_MIN_SIGNALS` / `SOCIAL_MIN_SIGNALS` — минимум упоминаний в окне (5)
- `NEWS_RATIO_THRESHOLD` / `SOCIAL_RATIO_THRESHOLD` — доля в одну сторону (0.65)

Если алертов слишком мало — снижай пороги spike/ratio. Если слишком много
шума — повышай. Но помни: алерт всё равно требует совпадения ≥2 категорий,
так что даже при мягких порогах внутри одной категории лишнего спама быть
не должно.

## Запуск на GitHub Actions (бесплатно, без сервера)

Вместо постоянного процесса бот запускается по расписанию (раз в ~5 минут):
`run_once.py` делает один цикл «собрать данные -> проверить алерты -> отправить -> выйти».
База (история цен/OI и кулдауны) хранится между запусками в отдельной ветке `state`.

**Ограничения этого режима**
- GitHub запускает расписание «по возможности»: запуски часто опаздывают на 5-20 минут.
- Команды `/start` и `/status` в этом режиме не работают (нет процесса, который слушает Telegram). Алерты приходят.
- Если в репозитории 60 дней нет коммитов, расписание отключается. Любой коммит в `main` (или кнопка включения во вкладке Actions) возвращает его.
- Публичный репозиторий: минуты бесплатные. В приватном есть месячный лимит минут, раз в 5 минут он, скорее всего, не хватит (актуальный лимит смотри в Settings -> Billing).
- Биржи могут блокировать IP облачных раннеров. В логе каждого запуска есть строка «Доступность бирж с этого IP»: HTTP 200 значит всё хорошо, HTTP 403/451 значит биржа блокирует.

**Настройка**
1. Создай репозиторий на GitHub (лучше публичный) и загрузи в него все файлы проекта, включая папку `.github`.
2. Settings -> Secrets and variables -> Actions -> **Secrets**: добавь `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и (по желанию) `CRYPTOPANIC_API_KEY`.
3. Вкладка **Actions** -> workflow `futures-bot` -> **Run workflow** (ручной тестовый запуск). Открой запуск и посмотри лог.
4. Дальше он идёт сам по расписанию.

**Как обновлять бота**
- Изменил код: коммит в `main` (через `git push` или прямо в веб-интерфейсе GitHub: открыть файл -> значок карандаша -> Commit). Следующий запуск по расписанию возьмёт новую версию.
- Изменил пороги: Settings -> Secrets and variables -> Actions -> **Variables** (например, `MARKET_PRICE_SPIKE_PCT`). Коммит не нужен.
- Сменил токен или ключи: там же, раздел Secrets.
- Не коммить `.env` и файлы `*.db` (они уже в `.gitignore`).

### Как показать команды `/start` и `/status`

В режиме cron команд нет: процесс живёт один цикл и завершается. Для демонстрации есть отдельный workflow **`bot-live`**: Actions → `bot-live` → **Run workflow** — бот поднимается с polling на 14 минут, и в это время `/start` и `/status` отвечают в Telegram. База перед запуском восстанавливается из ветки `state`, поэтому `/status` показывает сигналы, собранные прошлыми запусками.

Для постоянной работы команд нужен хост с долгоживущим процессом (VPS, Oracle Cloud Always Free и т. п.): `python main.py` под systemd, токен в `.env`.

## Архитектура проекта

Код разделён на слои: точка входа не знает, как собираются данные, сервис не знает, как доставляются уведомления, а коллекторы — как всё это хранится.

```
main.py / run_once.py      точки входа (Telegram-бот и один цикл по cron)
        │
        ▼
service.py                 сервисный слой: цикл сбора и проверки алертов
        │
        ├── collectors/     сбор данных: биржи, RSS, CryptoPanic, Reddit, Fear & Greed
        ├── alert_engine.py правила срабатывания алертов (2 категории + кулдаун)
        ├── db.py           доступ к данным (SQLite): сигналы, снапшоты, кулдауны
        └── notifier        функция доставки, передаётся снаружи (Telegram или заглушка в тестах)
```

| Модуль | Ответственность |
|---|---|
| `service.py` | один цикл: собрать → проверить → отдать алерты в notifier |
| `alert_engine.py` | решает, есть ли подтверждённый сигнал, и формирует текст алерта |
| `db.py` | схема SQLite и запросы, без бизнес-логики |
| `collectors/*` | источники данных, каждый умеет только собирать |
| `main.py` | долгоживущий процесс: aiogram + планировщик |
| `run_once.py` | один цикл для GitHub Actions |
| `markets.py` | топ-10 монет с кэшем на сутки |

Схема БД: `signals` (сигналы, дедупликация по `source+url`), `alert_state` (время последнего алерта для кулдауна), `market_snapshots` (срезы цены/funding/OI).

## Тесты

```bash
pip install -r requirements-dev.txt
pytest -q
```

20 тестов: `tests/test_db.py` (вставка, дедупликация, окно времени, кулдаун, очистка), `tests/test_alert_engine.py` (срабатывание только при двух категориях, противоположные направления, пороги, кулдаун), `tests/test_service.py` (сервисный слой с заглушками вместо сети и Telegram). К сети тесты не обращаются: база подменяется на временный файл, коллекторы — через `monkeypatch`.

## Запуск в Docker

```bash
cp .env.example .env      # заполнить токены
docker compose up -d --build
docker compose logs -f bot
```

`Dockerfile` собирает образ на `python:3.12-slim`, запускает бота от непривилегированного пользователя и содержит `HEALTHCHECK` (проверка доступности БД). `docker-compose.yml` поднимает бота с файлом `.env` и томом `bot_data` для базы.

## CI

`.github/workflows/ci.yml` на каждый push и pull request: установка зависимостей → `ruff check` → `pytest`. Отдельный workflow `bot.yml` — запуск бота по расписанию.

## Что показать на защите

1. `pytest -q` — 20 тестов, все зелёные.
2. `ruff check . --exclude venv --select E9,F` — без ошибок.
3. `docker compose up -d --build` и `docker compose ps` — контейнер в статусе `healthy`.
4. Вкладка Actions репозитория: прогон `ci` и запуски `futures-bot` по расписанию.
5. `python run_once.py` — один цикл в логе: сколько сигналов собрано, есть ли алерты.
6. Алерт в Telegram (или строка «НЕ отправлен» в логе, если токена нет).
7. Схема БД: `sqlite3 futures_bot.db ".tables"`.
